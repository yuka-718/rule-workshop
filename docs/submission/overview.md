# ルール工房 - 作品紹介

そのルールが、パズルになる。

公開サイト: https://yuka-718.github.io/rule-workshop/
ソースコード: https://github.com/yuka-718/rule-workshop

## 何を解決するか

パズルを自分で作ると、条件が矛盾して解けなかったり、答えが何通りも残ったりすることがあります。ルール工房は、短いRubyの条件式から全候補を調べ、答えの数を見ながらルールを調整できる制作ツールです。対象は、パズルを作って友人に遊んでもらいたい人や、条件式と論理に触れてみたい人です。

## 体験

1. サンプルのRuby DSLを編集する。
2. ルールを調べる。解の総数に加え、上から順にルールを加えたときの絞り込みを見る。
3. 問題を作る。答えがひとつになるように固定ヒントを残す。
4. クリック・タップ・キーボードで遊ぶ。空欄は青とは別に扱う。
5. URLまたは問題ファイルを共有する。受け手はルールを確認してから読み込む。

## Rubyならではの設計

Rubyが構文解析、盤面、条件評価、全探索、問題生成、正解判定を担います。BoardはEnumerableを利用し、Parserが認めた条件をProcとして組み立て、RuleとPuzzleでまとめます。画面のJavaScriptは入力と表示、保存、Workerとのデータ受け渡しを担当します。

Ripperで構文木を読み、許可した構文とメソッドだけを解釈します。ユーザー入力をそのままevalへ渡す方式ではありません。これはRubyの全機能を実行するエディターではなく、Rubyの構文を利用した専用DSLです。

## 小さく絞る理由

3×3・赤と青の2色なら完成盤面は2の9乗、512通りです。この範囲をすべて調べるため、解数を推定せずに計算できます。赤が3マスという条件だけなら84通り、さらに赤の上下左右の隣接を禁止すると22通りです。

生成は、全解から1つを選び、最初に9マスを固定した後、一意解を保てるヒントを順に外します。最後にも解が1つであることを確認します。ヒント数の大域的な最小化は保証しません。

## 利用者に合わせた改善

エラー行への移動、変更前と今回の解数の比較、自作ルールの復元、色を選んで塗る操作、1手戻す、キーボードでエディターを出る方法、長いURLの代わりになる問題ファイルを用意しました。赤は丸・青は四角で表し、色だけで識別させません。入力が揃うまでは単なるルール違反にせず「入力中」と表示します。

## 公開と動作環境

GitHub Pagesで公開します。ブラウザのWorker内でruby.wasmを動かし、バックエンド・データベース・APIキーは不要です。Ruby WASMとJavaScriptは同じ公開サイトから配信します。初回は約30MBのWASMを読み込むため、ネットワーク接続が必要です。

Chrome / Firefox / WebKitの自動検証結果と制約は、同梱の検証記録を参照してください。実機の全端末での動作を保証するものではありません。
