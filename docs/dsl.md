# Ruby DSLの書き方

```ruby
puzzle "赤を3つ、くっつけずに" do
  size 3, 3
  colors :red, :blue

  rule "赤はちょうど3マス" do |b|
    b.count(:red) == 3
  end

  rule "赤どうしは上下左右に隣り合わない" do |b|
    !b.adjacent?(:red)
  end
end
```

先頭にpuzzleを1つ。size、colorsをこの順に1回ずつ書き、その後にruleを0〜24個書きます。puzzleとruleの名前は1〜80文字。ルールの式は1つで、結果が真偽値になる必要があります。`#` のコメントと空行は利用できます。文字列は名前だけに使用でき、式展開は拒否します。名前のエスケープ表現は解釈せず、Ripperの文字列内容を表示するため、普通の文字を直接書いてください。

## 盤面の操作

| メソッド | 引数 | 結果 |
|---|---|---|
| `b.count(:red)` | :red または :blue | 盤面全体の個数（0〜9） |
| `b.cell(1, 2)` | 行、列（1〜3） | :red または :blue |
| `b.row_count(1, :red)` | 行（1〜3）、色 | その行の個数（0〜3） |
| `b.col_count(2, :blue)` | 列（1〜3）、色 | その列の個数（0〜3） |
| `b.adjacent?(:red)` | 色 | 同色が上下左右に隣接していればtrue。斜めは対象外 |

メソッドの引数は数値または色のリテラルのみです。式から算出した引数は未対応です。

## 式

- リテラル: 整数0〜9、`:red`、`:blue`、`true`、`false`。
- 比較: `==`、`!=` は同じ型の値同士。`<`、`<=`、`>`、`>=` は整数同士。
- 論理: `&&`、`||` は真偽値同士。`!` は真偽値1つに対して使用。
- 括弧: 式をまとめる。例: `(b.count(:red) == 3 || b.count(:red) == 4) && b.cell(2, 2) == :red`。

ブロックの引数は `|b|` 固定です。`do ... end` と、メソッド引数の括弧が必要です。`and` / `or` / `not`、波括弧のブロック、代入、配列・ハッシュ、加減算、動的な色名は未対応です。

## エラー

構文エラーや拒否された式は、取得できる場合に行番号を表示します。「エラー行へ」でエディターの該当行を選択します。ルールの矛盾は文法エラーとは別に、絞り込みの表で0通りになった段階を示します。


- 「Rubyの構文エラー」: 括弧・do/end・引用符を確認。
- 「対応メソッド…」: 許可された5メソッド以外を使っている。
- 「比較する値の型をそろえてください」: 数と色などを比較している。
- 「各ルールはtrue/falseになる式」: countだけを書いたなど、条件式になっていない。
- 「式が複雑すぎます」: 深さ64または構文木2,048ノードを超過。
- 「解がありません」: 文法が正しくても矛盾する条件がある。
- 「遊ぶ空欄が残りません」: ルールが弱く全マス固定が必要。条件を追加する。

## 入力制限と安全対策

ユーザーのRubyはRipperによる解析対象のデータです。eval、instance_eval、class_evalに渡しません。定数、require、ファイル・ネットワーク操作、任意の呼び出し、send/public_send、ループ、メソッド・クラス定義、文字列の式展開を拒否。論理演算の右辺も実行前に検査するため、`true || 危険な式` のような形も許可しません。

入力8,192 UTF-8バイト、24ルール、構文木の深さ64、2,048配列ノードまで。API JSONは65,536バイト、共有ハッシュは24,000文字まで。数値は0〜9の1桁リテラルだけです。512候補の全探索と9回のヒント除去に範囲を限定しています。

Workerの計算は8秒で停止して再起動できます。WASM初期ロードは別の120秒制限。DOMへの外部文字列の表示はtextContent / valueを使い、HTMLとして解釈しません。外部共有コードは確認ボタン前には評価しません。

これらはリスクを抑える設計であり、完全な安全性を保証するものではありません。ブラウザ・Ruby・WASMランタイムの脆弱性、端末の資源制限、URLを受け渡すアプリの長さ制限は別途影響します。
